    Code Snippet: Transactional Outbox Pattern for Order Placement (C# .NET 8)

    C#OrderService.cs
    public async Task<Guid> CreateOrderAsync(CreateOrderCommand command, CancellationToken ct)
{
    using var transaction = await _dbContext.Database.BeginTransactionAsync(ct);
    try
    {
        // 1. Domain Logic: Create Order
        var order = Order.Create(command.CustomerId, command.Items);
        _dbContext.Orders.Add(order);

        // 2. Persist Integration Event to Outbox in the SAME Transaction
        var outboxMessage = new OutboxMessage
        {
            Id = Guid.NewGuid(),
            OccurredOnUtc = DateTime.UtcNow,
            Type = typeof(OrderCreatedEvent).Name,
            Content = JsonSerializer.Serialize(new OrderCreatedEvent(order.Id, order.CustomerId, order.TotalAmount))
        };
        _dbContext.OutboxMessages.Add(outboxMessage);

        // 3. Commit Database Transaction
        await _dbContext.SaveChangesAsync(ct);
        await transaction.CommitAsync(ct);

        return order.Id;
    }
    catch (Exception)
    {
        await transaction.RollbackAsync(ct);
        throw;
    }
}

    To modernize legacy enterprise applications without a high-risk full rewrite:

    1. Interception Layer: Introduce API Gateway (YARP / Kong) in front of the monolith.
    2. Module Decoupling: Isolate domain bounds inside monolith (Modular Monolith refactor).

    How Would You Scale an Order Service?

    Scaling an Order Service to handle unpredictable peak volume spikes requires isolating read and write workloads and leveraging asynchronous event processing.

    Scaling Dimensions

    1. Read/Write Segregation (CQRS):
      • Write Path: High-throughput transaction handling using PostgreSQL horizontal partition (sharding) on CustomerId or OrderDate.
      • Read Path: Serve 95% of queries ("View Order History") from Redis or PostgreSQL Read Replica endpoints.
    2. Database Sharding & Connection Pooling:
      • Implement PgBouncer connection pooling to restrict active connection saturation.
      • Hash-based sharding strategy: ShardKey = Hash(CustomerId) % ShardCount.
    3. Event-Driven Asynchronous Processing:
      • Offload non-critical post-creation steps (email generation, loyalty points update, analytics) to RabbitMQ background workers.
    4. KEDA Driven Auto-Scaling on Kubernetes:

    Design Inventory Management

    Preventing overselling while sustaining thousands of concurrent checkouts during flash sales requires strict dynamic locking and state reservations.

    Soft Locking vs Hard Locking

    Soft Locking (In-Memory)

    Reserves stock in Redis for a configurable TTL (e.g., 10 minutes) during checkout flow. If user abandons cart, key expires and stock automatically returns to pool.

    Hard Locking (Relational DB)

    Atomically decrements the canonical row stock in PostgreSQL using row-level locking (SELECT ... FOR UPDATE) upon payment approval.

    Lua Script for Atomic Inventory Deduction in Redis

    To avoid race conditions, inventory deduction and check execute as an atomic single-threaded operation inside Redis:

    Luareserve_stock.lua
    -- KEYS[1]: Inventory Key (e.g., "inv:prod_10293")
-- ARGV[1]: Quantity to reserve
local current_stock = redis.call('get', KEYS[1])
if not current_stock then
    return -1 -- Stock key does not exist
end

local stock_num = tonumber(current_stock)
local req_num = tonumber(ARGV[1])

if stock_num >= req_num then
    redis.call('decrby', KEYS[1], req_num)
    return stock_num - req_num -- Return remaining stock
else
    return -2 -- Insufficient stock
end

    Design Cart Service

    The Cart Service demands high availability and sub-millisecond latency. A session-bound or user-bound key-value store fulfills these SLAs cleanly.

    Redis Data Structure Strategy

    Using Redis Hashes allows updating, incrementing, or deleting individual items without serializing/deserializing the entire cart payload.

    Key Format

    cart:user:{UserId}

    Fields

    Product SKU

    Value

    Serialized JSON { Quantity, AddedTimestamp, UnitPrice }

    Redis Cart Merge Implementation (C# .NET 8)

    C#CartService.cs
    public async Task MergeAnonymousCartAsync(string anonymousId, string userId)
{
    var anonKey = $"cart:anon:{anonymousId}";
    var userKey = $"cart:user:{userId}";

    var database = _redis.GetDatabase();

    // Fetch all items from anonymous cart
    var anonItems = await database.HashGetAllAsync(anonKey);
    if (anonItems.Length == 0) return;

    var transaction = database.CreateTransaction();

    foreach (var item in anonItems)
    {
        // Add or increment quantities in authenticated cart
        transaction.HashSetAsync(userKey, item.Name, item.Value);
    }

    // Delete anonymous cart after merge
    transaction.KeyDeleteAsync(anonKey);

    await transaction.ExecuteAsync();
}

    {

    CQRS Implementation

    Command Query Responsibility Segregation (CQRS) decouples write operations (Commands) from read operations (Queries) to maximize performance and scalability.

    MediatR Implementation (C# .NET 8)

    Command Side (EF Core — Transactional Write)

    C#CreateOrderCommandHandler.cs
    public record CreateOrderCommand(Guid CustomerId, List<OrderItemDto> Items) : IRequest<Guid>;

public class CreateOrderCommandHandler : IRequestHandler<CreateOrderCommand, Guid>
{
    private readonly ApplicationDbContext _db;
    public CreateOrderCommandHandler(ApplicationDbContext db) => _db = db;

    public async Task<Guid> Handle(CreateOrderCommand request, CancellationToken cancellationToken)
    {
        var order = new Order(request.CustomerId);
        foreach (var item in request.Items)
            order.AddItem(item.ProductId, item.Quantity, item.UnitPrice);

        _db.Orders.Add(order);
        await _db.SaveChangesAsync(cancellationToken);
        return order.Id;
    }
}

    Query Side (Dapper — Ultra-Fast Read)

    C#GetOrderByIdQueryHandler.cs
    public record GetOrderByIdQuery(Guid OrderId) : IRequest<OrderDetailsDto?>;

public class GetOrderByIdQueryHandler : IRequestHandler<GetOrderByIdQuery, OrderDetailsDto?>
{
    private readonly IDbConnectionFactory _connectionFactory;
    public GetOrderByIdQueryHandler(IDbConnectionFactory connectionFactory) => _connectionFactory = connectionFactory;

    public async Task<OrderDetailsDto?> Handle(GetOrderByIdQuery request, CancellationToken cancellationToken)
    {
        using var connection = _connectionFactory.CreateConnection();
        const string sql = @"
            SELECT o.Id, o.CustomerId, o.TotalAmount, o.Status,
                   i.ProductId, i.Quantity, i.UnitPrice
            FROM Orders o
            LEFT JOIN OrderItems i ON o.Id = i.OrderId
            WHERE o.Id = @OrderId";

        var orderMap = new Dictionary<Guid, OrderDetailsDto>();
        await connection.QueryAsync<OrderDetailsDto, OrderItemDto, OrderDetailsDto>(
            sql,
            (order, item) =>
            {
                if (!orderMap.TryGetValue(order.Id, out var currentOrder))
                {
                    currentOrder = order;
                    currentOrder.Items = new List<OrderItemDto>();
                    orderMap.Add(currentOrder.Id, currentOrder);
                }
                if (item != null) currentOrder.Items.Add(item);
                return currentOrder;
            },
            new { request.OrderId },
            splitOn: "ProductId");

        return orderMap.Values.FirstOrDefault();
    }
}

    Saga Pattern

    Orchestration vs Choreography

    Choreography

    Microservices publish and listen to events independently without a central controller. Best for simple workflows.

    Orchestration

    A central Saga Orchestrator coordinates workflow execution, dictates execution paths, and triggers compensating commands on failures. Best for complex enterprise workflows.

    State Machine Implementation with MassTransit (C# .NET 8)

    C#OrderSagaOrchestrator.cs
    public class OrderSagaState : SagaStateMachineInstance
{
    public Guid CorrelationId { get; set; }
    public string CurrentState { get; set; } = null!;
    public Guid OrderId { get; set; }
    public decimal Amount { get; set; }
}

public class OrderSagaOrchestrator : MassTransitStateMachine<OrderSagaState>
{
    public State ProcessingPayment { get; private set; } = null!;

    public Event<OrderCreatedEvent> OrderCreated { get; private set; } = null!;
    public Event<PaymentFailedEvent> PaymentFailed { get; private set; } = null!;

    public OrderSagaOrchestrator()
    {
        InstanceState(x => x.CurrentState);

        Event(() => OrderCreated, x => x.CorrelateById(m => m.Message.OrderId));
        Event(() => PaymentFailed, x => x.CorrelateById(m => m.Message.OrderId));

        Initially(
            When(OrderCreated)
                .Then(context => context.Saga.Amount = context.Message.TotalAmount)
                .TransitionTo(ProcessingPayment)
                .Publish(context => new ProcessPaymentCommand(context.Saga.OrderId, context.Saga.Amount))
        );

        During(ProcessingPayment,
            When(PaymentFailed)
                .Publish(context => new CompensateInventoryCommand(context.Saga.OrderId))
                .Finalize()
        );
    }
}

    Retry Policy (Exponential Backoff & Jitter)

    Re-trying transient errors immediately can overwhelm a struggling downstream service (thundering herd problem). Jitter introduces randomness to retry delays to distribute request volume evenly over time.

    Calculated Delay FormulaDelay = Min(Max_Delay, Base_Delay * 2 ^ Attempt) + Random_Jitter

    Polly Implementation with Exponential Backoff + Jitter

    C#RetryPipeline.cs
    var retryPipeline = new ResiliencePipelineBuilder<HttpResponseMessage>()
    .AddRetry(new RetryStrategyOptions<HttpResponseMessage>
    {
        ShouldHandle = new PredicateBuilder<HttpResponseMessage>()
            .HandleResult(res => res.StatusCode == HttpStatusCode.ServiceUnavailable),
        MaxRetryAttempts = 4,
        BackoffType = DelayBackoffType.Exponential,
        Delay = TimeSpan.FromSeconds(1),
        UseJitter = true // Adds full randomized jitter
    })
    .Build();

    Idempotency

    An idempotent endpoint yields the exact same state outcome regardless of how many times the request executes with identical payloads.

    ASP.NET Core Idempotency Middleware Implementation

    C#IdempotencyMiddleware.cs
    public class IdempotencyMiddleware
{
    private readonly RequestDelegate _next;
    private readonly IDistributedCache _cache;

    public IdempotencyMiddleware(RequestDelegate next, IDistributedCache cache)
    {
        _next = next;
        _cache = cache;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        if (context.Request.Method != HttpMethods.Post)
        {
            await _next(context);
            return;
        }

        if (!context.Request.Headers.TryGetValue("X-Idempotency-Key", out var idempotencyKey))
        {
            await _next(context);
            return;
        }

        var cacheKey = $"idempotency:{idempotencyKey}";
        var cachedResponse = await _cache.GetStringAsync(cacheKey);

        if (cachedResponse != null)
        {
            context.Response.ContentType = "application/json";
            context.Response.StatusCode = StatusCodes.Status200OK;
            await context.Response.WriteAsync(cachedResponse);
            return;
        }

        // Capture downstream response body
        var originalBodyStream = context.Response.Body;
        using var responseBody = new MemoryStream();
        context.Response.Body = responseBody;

        await _next(context);

        if (context.Response.StatusCode is StatusCodes.Status200OK or StatusCodes.Status201Created)
        {
            responseBody.Seek(0, SeekOrigin.Begin);
            var responseText = await new StreamReader(responseBody).ReadToEndAsync();
            
            // Cache successful payload for 24 hours
            await _cache.SetStringAsync(cacheKey, responseText, new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromHours(24)
            });

            responseBody.Seek(0, SeekOrigin.Begin);
            await responseBody.CopyToAsync(originalBodyStream);
        }
    }
}

    Redis Caching Strategy

    Cache-Aside Pattern with Mutex (Mitigating Cache Stampede)

    C#CatalogCacheService.cs
    public async Task<ProductDto?> GetProductAsync(Guid productId, CancellationToken ct)
{
    var cacheKey = $"catalog:product:{productId}";
    var cachedData = await _cache.GetStringAsync(cacheKey, ct);

    if (cachedData != null)
        return JsonSerializer.Deserialize<ProductDto>(cachedData);

    // Acquire distributed lock to prevent thundering herd against primary DB
    var lockKey = $"lock:product:{productId}";
    var isLocked = await _redisDb.StringSetAsync(lockKey, "locked", TimeSpan.FromSeconds(5), QueueWhenLocked: false);

    if (!isLocked)
    {
        // Wait and fallback retry cache hit
        await Task.Delay(200, ct);
        return await GetProductAsync(productId, ct);
    }

    try
    {
        var product = await _dbContext.Products.AsNoTracking().FirstOrDefaultAsync(p => p.Id == productId, ct);
        if (product != null)
        {
            var dto = new ProductDto(product.Id, product.Name, product.Price);
            await _cache.SetStringAsync(cacheKey, JsonSerializer.Serialize(dto), new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(30)
            }, ct);
            return dto;
        }
        return null;
    }
    finally
    {
        await _redisDb.KeyDeleteAsync(lockKey);
    }
}

    Refactored (SOLID Compliant)

    // Single Responsibility Principle (SRP) & Dependency Inversion Principle (DIP)
public interface IOrderRepository { Task SaveAsync(Order order); }
public interface INotificationService { Task SendConfirmationEmailAsync(Order order); }

public class OrderProcessor // SRP: Focuses exclusively on order domain orchestration
{
    private readonly IOrderRepository _repository;
    private readonly INotificationService _notificationService;

    // Dependency Inversion Principle: Depend on abstractions, not concretions
    public OrderProcessor(IOrderRepository repository, INotificationService notificationService)
    {
        _repository = repository;
        _notificationService = notificationService;
    }

    public async Task ProcessAsync(Order order)
    {
        order.MarkAsProcessed();
        await _repository.SaveAsync(order);
        await _notificationService.SendConfirmationEmailAsync(order);
    }
}

    private readonly List<DomainEvent> _domainEvents = new();

    public Customer(Guid id, string name, Address shippingAddress)
    {
        Id = id;
        Name = Guard.Against.NullOrEmpty(name);
        ShippingAddress = Guard.Against.Null(shippingAddress);
    }

    public void UpdateAddress(Address newAddress)
    {
        ShippingAddress = Guard.Against.Null(newAddress);
        _domainEvents.Add(new CustomerAddressUpdatedEvent(Id, newAddress));
    }

    Blue-Green Deployment with Database Evolution

    Database Migration Strategy (Expand-Contract Pattern)

    1. Expand: Add new non-breaking column (e.g., add FullName alongside FirstName/LastName). Deploy DB migration first.
    2. Deploy Green: Deploy v2 microservices to Green environment configured to read/write to FullName. Both v1 (Blue) and v2 (Green) operate safely in parallel.
    3. Switch Traffic: Route 100% gateway traffic to Green.
    4. Contract: Drop obsolete FirstName/LastName columns in a subsequent cleanup DB migration once v1 is decommissioned.

    AI Integration into Enterprise Applications

    Integrating Large Language Models (LLMs) securely with enterprise microservices using Retrieval-Augmented Generation (RAG).

    Low-Level Design (LLD): Semantic Kernel RAG Service (C# .NET 8)

    C#AIRecommendationService.cs
    public class AIRecommendationService
{
    private readonly Kernel _kernel;
    private readonly VectorStoreClient _vectorStore;

    public AIRecommendationService(Kernel kernel, VectorStoreClient vectorStore)
    {
        _kernel = kernel;
        _vectorStore = vectorStore;
    }

    public async Task<string> GetProductRecommendationAsync(string customerQuery, Guid customerId)
    {
        // 1. Perform Vector Similarity Search in Enterprise Catalog Index
        var vectorSearchResults = await _vectorStore.SearchAsync(
            collectionName: "product-catalog",
            query: customerQuery,
            limit: 3
        );

        var contextPayload = string.Join("\n", vectorSearchResults.Select(r => r.Description));

        // 2. Build Grounded Prompt with Context Isolation
        var prompt = $"""
            You are an expert enterprise shopping assistant.
            Answer the user query based ONLY on the contextual product information provided below.
            Do not use outside knowledge. If the answer cannot be found, say 'I cannot assist with that product.'

            [Context Data]
            {contextPayload}

            [User Question]
            {customerQuery}
            """;

        // 3. Invoke LLM via Semantic Kernel Integration
        var result = await _kernel.InvokePromptAsync(prompt);
        return result.ToString();
    }
}
