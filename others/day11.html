1. Authentication and Authorization

Authentication (Who are you?)

Authentication verifies the identity of a user or service. Common methods:

  • JWT Tokens: Stateless tokens containing user claims
  • OAuth 2.0: Delegated authorization framework
  • OpenID Connect: Authentication layer on top of OAuth
  • API Keys: Simple tokens for service-to-service communication
Best Practice: Use Azure AD B2C or IdentityServer for authentication. Never store passwords in plain text.

Authorization (What can you do?)

Authorization determines what resources a user can access. Common approaches:

  • Role-Based Access Control (RBAC): Users assigned to roles, roles have permissions
  • Claims-Based: Fine-grained permissions based on user claims
  • Policy-Based: Complex authorization rules based on multiple factors

Implementation Example: JWT + RBAC

// 1. Authentication (JWT)
[HttpPost("login")]
public async Task<IActionResult> Login([FromBody] LoginRequest request)
{
    var user = await _userService.AuthenticateAsync(request.Username, request.Password);
    if (user == null)
        return Unauthorized();

    var claims = new[]
    {
        new Claim(ClaimTypes.Name, user.Username),
        new Claim(ClaimTypes.Role, user.Role),
        new Claim("TenantId", user.TenantId.ToString())
    };

    var key = new SymmetricSecurityKey(_config.GetRaw("Jwt:Key"));
    var creds = new SigningCredentials(key, SecurityAlgorithms.HmacSha256);
    
    var token = new JwtSecurityToken(
        issuer: _config["Jwt:Issuer"],
        audience: _config["Jwt:Audience"],
        claims: claims,
        expires: DateTime.UtcNow.AddHours(1),
        signingCredentials: creds
    );

    return Ok(new { token = new JwtSecurityTokenHandler().WriteToken(token) });
}

// 2. Authorization (Role-based)
[Authorize(Roles = "Admin")]
[HttpGet("users")]
public IActionResult GetAllUsers()
{
    // Only admins can access this
    return Ok(_userService.GetAllUsers());
}

[Authorize]
[HttpGet("orders")]
public IActionResult GetMyOrders()
{
    // Any authenticated user can access their own orders
    var userId = User.FindFirst(ClaimTypes.NameIdentifier).Value;

Multi-Tenant Authorization

// Ensure users can only access their tenant's data
public class TenantAuthorizationHandler : AuthorizationHandler<TenantRequirement>
{
    protected override Task HandleRequirementAsync(
        AuthorizationHandlerContext context, 
        TenantRequirement requirement)
    {
        var tenantId = int.Parse(
            context.User.FindFirst("TenantId")?.Value ?? "0");
        
        var requestedTenantId = int.Parse(
            context.Resource?.ToString() ?? "0");

        if (tenantId == requestedTenantId)
        {
            context.Succeed(requirement);
        }

        return Task.CompletedTask;
    }
}

// Usage
[Authorize(Policy = "TenantAccess")]
[HttpGet("tenants/{tenantId}/data")]
public IActionResult GetTenantData(int tenantId)
{
    // Only users from this tenant can access
    return Ok(_service.GetData(tenantId));
}

2. API Security

Input Validation and Sanitization

// Validate input at the API boundary
public class CreateOrderRequest
{
    [Required]
    [StringLength(100)]
    public string CustomerName { get; set; }

    [Required]
    [EmailAddress]
    public string Email { get; set; }

    [Required]
    [Range(0.01, 10000)]
    public decimal Amount { get; set; }
}

// Sanitize to prevent injection attacks
public string SanitizeInput(string input)
{
    // Remove dangerous characters
    return input.Replace("<", "<")
                .Replace(">", ">")
                .Replace("'", "''")
                .Replace("\"", "\"\"");
}

Rate Limiting

// Rate limiting to prevent abuse
services.AddRateLimiter(options =>
{
    options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(
        httpContext => RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: httpContext.User.Identity?.Name ?? httpContext.Connection.RemoteIpAddress.ToString(),
            factory: _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 100,
                Window = TimeSpan.FromMinutes(1)
            }));

    options.RejectionStatusCode = 429; // Too Many Requests
});

Security Headers

// Add security headers to all responses
app.Use(async (context, next) =>
{
    context.Response.Headers.Add("X-Content-Type-Options", "nosniff");
    context.Response.Headers.Add("X-Frame-Options", "DENY");
    context.Response.Headers.Add("X-XSS-Protection", "1; mode=block");
    context.Response.Headers.Add("Strict-Transport-Security", "max-age=31536000");
    await next();
});

3. Data Protection

Encryption at Rest

  • Azure SQL: Transparent Data Encryption (TDE)
  • Azure Blob Storage: Server-side encryption
  • Azure Key Vault: Encrypt sensitive configuration

Encryption in Transit

  • Always use HTTPS/TLS for all communication
  • Use managed certificates (Azure Key Vault or App Service)
  • Enforce HTTPS in ASP.NET Core: app.UseHttpsRedirection();

Sensitive Data Handling

// Never log sensitive data
public class RedactingLogger : ILogger
{
    public void Log<TState>(LogLevel logLevel, EventId eventId, 
        TState state, Exception exception, 
        Func<TState, Exception, string> formatter)
    {
        var message = formatter(state, exception);
        
        // Redact sensitive information
        message = Regex.Replace(message, 
            @"password=([^&]+)", "password=***", RegexOptions.IgnoreCase);
        
        // Log the sanitized message
        _logger.Log(logLevel, eventId, message, exception, 
            (s, ex) => s);
    }
}

// Encrypt sensitive fields in database
public class User
{
    public int Id { get; set; }
    public string Username { get; set; }
    
    [Encrypted]
    public string SSN { get; set; } // Encrypted at rest
    
    [Encrypted]
    public string CreditCardNumber { get; set; }
}

4. Multi-Tenant Security

Critical: Tenant isolation must be enforced at EVERY layer:

  • Database queries (WHERE clauses)
  • API authorization (policies)
  • Cache keys (tenant-specific prefixes)
  • Logging (tenant context)
  • Background jobs (tenant scope)

Database-Level Tenant Isolation

// EF Core Global Query Filter
public class ApplicationDbContext : DbContext
{
    private readonly int _tenantId;

    public ApplicationDbContext(DbContextOptions options, 
        ITenantProvider tenantProvider) : base(options)
    {
        _tenantId = tenantProvider.GetTenantId();
    }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        // Apply tenant filter to all entities with TenantId
        modelBuilder.Entity<Order>()
            .HasQueryFilter(o => o.TenantId == _tenantId);
        
        modelBuilder.Entity<Customer>()
            .HasQueryFilter(c => c.TenantId == _tenantId);
    }
}

// Tenant provider from JWT
public class JwtTenantProvider : ITenantProvider
{
    private readonly IHttpContextAccessor _httpContext;

    public int GetTenantId()
    {
        var tenantClaim = _httpContext.HttpContext
            .User.FindFirst("TenantId");
        
        return int.Parse(tenantClaim?.Value ?? "0");
    }
}

Multi-Tenant Caching

// Tenant-specific cache keys
public class TenantCacheService
{
    private readonly IDistributedCache _cache;
    private readonly int _tenantId;

    public async Task<T> GetAsync<T>(string key)
    {
        // Include tenant ID in cache key
        var tenantKey = $"tenant:{_tenantId}:{key}";
        var value = await _cache.GetStringAsync(tenantKey);
        
        return value != null ? JsonSerializer.Deserialize<T>(value) : default;
    }

    public async Task SetAsync<T>(string key, T value, TimeSpan expiration)
    {
        var tenantKey = $"tenant:{_tenantId}:{key}";
        await _cache.SetStringAsync(tenantKey, 
            JsonSerializer.Serialize(value),
            new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = expiration
            });
    }
}

5. Security Failure Scenarios

Failure Scenario Business Impact Architecture Response
JWT token stolen Attacker impersonates user Short token lifetime (1 hour), refresh token rotation, token revocation list
User role changed User retains old permissions Token validation checks current role, force re-authentication on role change
API key leaked Unauthorized service access Key rotation, rate limiting, IP whitelisting
Tenant isolation breach Data leak between tenants Database-level filters, API-level policies, audit logging
Brute force attack Account takeover Rate limiting, account lockout, CAPTCHA, MFA
Sensitive data logged Compliance violation, data breach Log sanitization, structured logging with redaction

🚨 Attack Scenarios to Handle

Scenario 1: User changes tenant ID manually

Question: How does your architecture handle this?

Solution: Tenant ID comes from JWT token, not from request body. Database-level global query filter ensures tenant isolation. API-level authorization validates tenant context.

Scenario 2: Stolen access token

Question: How does your architecture handle this?

Solution: Short token lifetime (1 hour), refresh token rotation, token revocation list, suspicious activity detection.

Scenario 3: Leaked API key

Question: How does your architecture handle this?

Solution: Key rotation, rate limiting, IP whitelisting, audit logging of key usage.

Scenario 4: Admin permission accidentally given to employee

Question: How does your architecture handle this?

Solution: Role changes require re-authentication, audit logging of role assignments, approval workflow for admin roles.

Scenario 5: Login endpoint receives huge traffic

Question: How does your architecture handle this?

Solution: Rate limiting on login endpoint, account lockout after failed attempts, CAPTCHA, DDoS protection.

10. Self-Test

Question 1

What is the difference between authentication and authorization?

Answer: Authentication verifies identity (who you are). Authorization determines permissions (what you can do).

Question 2

Why use JWT tokens instead of sessions?

Answer: JWT is stateless (no server-side storage), scalable (works across services), and self-contained (contains user claims).

Question 3

How do you prevent tenant isolation breaches?

Answer: Multi-layer approach: database-level query filters, API-level authorization, tenant context from JWT, audit logging.

Question 4

What happens when a user's role is changed?

Answer: Force re-authentication to get new token with updated role claims. Old token becomes invalid.

Question 5

How do you secure service-to-service communication?

Answer: Use managed identity or service principals, JWT tokens, HTTPS, API keys stored in Key Vault.
